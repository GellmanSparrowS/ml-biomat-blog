样品多起来以后，怎样让每个数字都找得到主人？

第一章只处理一块凝胶，干质量和湿质量放在两个变量里就能说清。现在准备比较水浴和盐水浴中的六个样品，每个样品还带有编号、处理条件和温度。如果继续写dry_1、dry_2、wet_1、wet_2，程序很快就会变成一长串需要人工配对的名字。更麻烦的是，某个样品少了一次称量，或者我们想按质量重新排列它们，原先靠位置记住的关系就可能错开。本章学习列表和字典，用结构把样品身份、条件和数值一起保存。

我们采用六条构造的教学记录。A01、A02、A03属于水浴，B01、B02、B03属于盐水浴；所有记录的温度字段均为25.0 °C。干质量分别为1.20、1.00、0.80、1.20、1.00、0.80 g，湿质量为4.80、3.40、2.80、3.60、缺失、2.32 g。这里的质量已经扣除容器。本例把干质量作为固定参照，增加的质量按所吸收液体计；盐水浴中吸收的液体包含水与溶解组分。编号前缀只是本例安排好的标签，实际分析仍读取明确的处理条件字段。这样，后续即使编号规则改变，也不会靠猜测字母来决定样品属于哪一组。

每条记录可以想成贴在样品袋上的一张完整标签：编号告诉我们是哪一件，条件告诉我们经历了什么，质量给出可计算的量。列表像一个有顺序的样品架，负责把多条记录收在一起；字典像标签上的“字段名—字段值”对应表，负责表达一条记录内部的含义。两者配合后，可以按位置取出第二条记录，也可以根据稳定的编号找到A02，取出的湿质量应是同一个3.40 g。

本章会从一个简单数字列表开始，逐步建立字典、记录列表和按编号查找的索引，再处理缺失值、排序与复制。最后的图和交互会展示一个容易被忽视的错误：同样的数字，只要干湿质量的对应关系改变，就会得到完全不同的吸液量。保持总数相同、数据没有报错，还不足以保证计算表达了原来的实验。

列表把一串值放在有顺序的位置上

列表用方括号包住多个值，值之间用逗号分隔，例如dry_masses = [1.2, 1.0, 0.8]。这里三个值依次对应三条记录。len(dry_masses)给出列表长度3，dry_masses[0]取出第一个值1.2。Python的位置索引从0开始，所以索引0、1、2分别对应人们口头说的第一、第二、第三项。可以把索引理解为从起点向后走了几步：第一项不需要移动，因而位置为0。

负索引从末尾开始找，dry_masses[-1]取最后一项0.8；切片dry_masses[0:2]则取得从位置0开始、到位置2之前的两项。右端不包含在结果中，这样[0:2]与[2:3]可以拼成原来的连续范围，而不会重复边界元素。切片得到的是一段序列，单个索引得到的是其中一个对象，两者在后续操作中扮演不同角色。刚开始使用时，把位置写在纸上，再预测取到哪些值，会比凭直觉记住冒号更牢靠。

位置、切片与添加

依次得到3；1.2与0.8；[1.2,1.0]；最后列表为[1.2,1.0,0.8,1.1]。

dry_masses = [1.2, 1.0, 0.8]
print(len(dry_masses))
print(dry_masses[0], dry_masses[-1])
print(dry_masses[0:2])
dry_masses.append(1.1)
print(dry_masses)

还要留意列表运算与数字运算的区别。两个列表相加会首尾连接，例如[1.2, 1.0] + [0.8]得到三个元素；列表乘以2会重复其中的序列，例如[1.2, 1.0] * 2得到四个元素，而不是把每个质量加倍。如果想改变每个数，需要逐项施加计算规则，后面的循环与NumPy数组会提供合适方式。遇到一个新对象时，先问运算符对这个对象代表什么，能够避免把熟悉的数学符号直接套进另一种数据结构。

列表可以改变。dry_masses.append(1.1)把一个新值添加到末尾；点号左边是要操作的对象，右边是它提供的操作名，括号里是这次操作需要的输入。这里的append会直接改变原列表，返回值为None，因此不要把它的返回值重新赋给列表名。dry_masses[1] = 1.05替换第二项，列表长度不变；删除一项则会让后面的项向前移动。位置描述的是当前排列，不能天然充当永远稳定的样品编号。

列表允许存放不同类型的值，但“可以存”与“这样组织容易理解”是两回事。把编号、质量和温度交错放进一个长列表，会迫使每次使用都记住哪个位置是什么。对于同一类连续观测，例如按时间记录的一组温度，列表非常自然；对于一个样品的多个不同字段，使用有名字的对应关系会更清楚。下一步引入字典，就是为了让字段含义直接出现在取值语句中，而不再依赖隐藏的位置约定。

字典让字段名称与值一起移动

字典用花括号表示，其中每一项由键、冒号和值组成。键是用来查找的名称，例如"dry_g"；值是对应内容，例如1.2。写成sample["dry_g"]，就取得这条样品记录的干质量。引号表明字段名是字符串，方括号中的键指定要找哪一项。一个字典可以同时容纳字符串、数字和缺失标记，因为它们分别描述不同字段。字段名中的单位后缀把上一章的单位约定保留在数据结构里。

按字段名读取和修改

先读取A01与4.8，未提供的note返回None；修改后wet_g为4.9。

sample = {"id": "A01", "bath": "water", "dry_g": 1.2, "wet_g": 4.8}
print(sample["id"], sample["wet_g"])
print(sample.get("note"))
sample["wet_g"] = 4.9
print(sample["wet_g"])

字典中的键是唯一的。给已经存在的键赋值，会更新对应值，而不是增加第二个同名字段。这带来方便，也要求我们认真处理编号：如果两条记录都用A01作为外层字典的键，后写入的值会覆盖先前的关联。因此在建立按编号查找的字典之前，先检查编号是否重复。set(ids)建立只保留不同编号的集合，把集合长度与原编号列表长度比较，就能发现是否有重复。集合在这里用于检查唯一性，不承担原始记录顺序的保存。

Python字典保留插入顺序，所以打印时通常能看到字段按建立时的顺序出现。不过按键查找依赖的是键的含义，不是它显示在第几行。sample["wet_g"]在字段排列改变后仍然读取湿质量。列表索引与字典键都写在方括号里，但查找规则不同：前者问“当前位置上是什么”，后者问“这个键对应什么”。把这两个问题分清，便能判断某个数据操作应该保持顺序，还是应该保持名称关联。

如果字段本来就应存在，直接使用方括号查找可以及时暴露拼写或结构问题；键不存在时会出现KeyError。sample.get("note")则适合读取确实可选的备注，缺少时返回默认值None。如果把必需的湿质量字段也随手设置默认0，程序可能继续运行，却把没有记录的称量解释成真实零质量。数据结构的选择与缺失处理是一件连贯的事：先决定哪些字段必须有，再决定缺失内容如何表达，最后决定哪些记录能够进入某个计算。

一条记录作为一个整体，排序才不会拆散实验

建立记录之前，还应定义“一条”究竟代表什么。本章一条记录对应一个样品的一次干湿称量配对，所以样品ID在表中唯一。如果同一个样品在10、20、30分钟分别称量，就会出现多次观测；可以给每次观测独立编号，并把样品ID与时间作为字段保存，也可以在样品记录中组织时间序列。此时样品ID重复并不一定是录入错误，是否允许重复取决于记录的单位。先确定这一层含义，唯一性检查才会检查正确的对象。

把六个样品字典放进一个列表，就得到记录列表records。records[1]是第二个字典，继续写["wet_g"]便取得它的湿质量；这个连续取值过程是先选样品，再选字段。也可以建立by_id字典，把每个样品编号映射到整条记录，随后用by_id["A02"]["wet_g"]直接查找。前者适合按当前顺序逐条处理，后者适合回答“某个样品现在在哪里”。两种结构可以引用同一批记录，并不一定复制一份新的实验数据。

排序时，应该让记录作为整体移动。按照干质量排列六条记录后，A01可能离开原来的列表位置，但它的编号、水浴条件、干质量和湿质量仍在同一个字典里。完整示例使用sorted产生排序后的新列表，原列表的顺序保留。排序键指定按哪个字段比较，这里是干质量；相同干质量的记录仍按原来的先后顺序出现。排序改变展示和遍历的次序，不应改变一条记录内部的科学含义。

看看只排序湿质量一列会怎样。三条水浴记录原先配对为1.20与4.80、1.00与3.40、0.80与2.80 g，吸液量分别为3.00、2.40、2.50 g/g。如果把湿质量单独升序排列，第一项变成2.80 g并与A01的1.20 g误配，最后一项4.80 g则与A03的0.80 g误配，结果变成约1.33、2.40、5.00 g/g。湿质量总和完全没变，每个数也仍像一个合理读数，但样品之间的关联已经被破坏。

这一问题与数据管理史中的一个重要方向相通。E. F. Codd在1970年提出关系数据模型时，讨论了怎样让使用者对数据的操作不必紧紧依附机器内部的存储安排。我们在小例子中采取的做法是把编号与测量关系明确保存，使重新排列不会改变“哪个值属于哪个样品”。普通Python字典提供按键查找，记录列表提供组织和遍历；当需要更大的数据表、关联查询和长期维护时，还会用到专门的表格与数据库工具。当前最值得掌握的原则，是把稳定身份与临时位置区分开。

没有称量，与称得零克，进入计算的方式不同

B02的湿质量写成None，表示这次称量没有提供数值。它与数字0有完全不同的含义：0 g是一条具有数值内容的记录，可能提示称量对象或过程需要检查；None表示这里尚无可代入公式的量。若用0替代缺失湿质量，按本章公式会得到−1 g/g，相当于声称整个干样质量都消失了。一个数据整理上的随手替换，就会变成一个强烈但没有测量支持的物理结论。

本章的规则是保留B02整条记录，把它的吸液量结果也记作None，仅在计算需要湿质量的统计量时跳过这一项。这样，记录总数仍为6，有效吸液量数为5；水浴组有3个有效结果，盐水浴组有2个。图中明确保留B02的位置并标注未称量，读者可以看见缺失发生在哪个样品。缺失记录仍包含有用的编号、干质量和处理条件，不能因为某个计算用不上它，就把这些信息一起抹去。

样品标识对应的索引，无量纲；始终在同一样品内配对
第i个样品按干质量归一化的吸液量，g/g，无量纲
第i个样品的净湿质量，g；缺失时不计算q
第i个样品的正净干质量，g
湿质量减干质量，得到本例中的留存液体质量

A02：(3.40−1.00)/1.00=2.40 g/g；B03：(2.32−0.80)/0.80=1.90 g/g。编号保持干湿质量属于同一样品；B02缺少湿质量，结果保留为None。

公式中的差值先取出每个样品留存的水，再除以该样品自己的干质量。A02的结果是(3.40−1.00)/1.00=2.40 g/g，B03的结果是(2.32−0.80)/0.80=1.90 g/g。代码使用is None检查缺失标记，而不是使用if not value这类把零、空字符串等情况一并当成假的判断。明确检查缺少的是什么，有助于让处理规则与记录含义一致。更复杂的表格缺失值会在pandas章节展开，这里先把最基本的区别建立稳固。

在进入计算前，程序还检查干质量是否为正，以及本例干物质质量保持不变的吸液设定下湿质量是否小于干质量。这些条件直接来自质量对象和公式分母。处理缺失与验证有效范围是两种不同操作：前者说明没有提供某个值，后者说明已提供的值是否满足当前计算条件。保持原始字段、另建结果字段，可以让这两个过程都看得清楚，并为以后更换分析规则留下可重新计算的原始记录。

汇总时保留样品点与有效计数

六条记录整理好后，最容易想做的是比较两组平均吸液量。但在计算之前，先把每个样品画出来，能看见组内差异和缺失位置。水浴组的三个值为3.00、2.40、2.50 g/g；盐水浴组的两个有效值为2.00、1.90 g/g。图中的每个点仍带着样品身份，组别用颜色区分；右侧的平均线则把这几个点汇总成一个代表值，同时显示进入平均的有效数量。一个均值不能替代构成它的记录。

所选处理组，如water或saline；组名，无量纲
该组中具有有效吸液量的样品集合
有效样品数，为正整数，无量纲
样品i的吸液量，g/g
每个有效样品等权的组平均吸液量，g/g
Σ表示逐个相加；∈表示索引属于有效样品集合

水浴组(3.00+2.40+2.50)/3=2.6333… g/g；盐水浴组(2.00+1.90)/2=1.95 g/g。没有有效结果时，均值应保留缺失，不能把空集合除以零。

这里采用每个有效样品等权的算术平均，水浴组为(3.00+2.40+2.50)/3≈2.6333 g/g，盐水浴组为(2.00+1.90)/2=1.95 g/g。分母使用有效结果数，而不是预先计划的样品数。若把盐水浴组的两个结果之和仍除以3，就等价于偷偷添加一个零结果，平均值会降低为1.30 g/g。公开分母和有效计数，使读者能够直接复算，而不必猜测缺失记录究竟怎样进入了汇总。

当记录增加时，字段的一致性也需要维护。"water"、"Water"和"water "是三个不同字符串，最后一个还带有空格；按文字分组时，它们会被当成不同条件。可以在读取阶段统一约定的大小写和空格处理，并保留真正不同的实验条件。温度为25与温度字段缺失也应分别表达。把清理规则集中应用在输入边界，比在每次求平均时临时修补更容易看清数据经历了什么变化。

每个样品的比值平均，还不同于先把各样品质量相加再计算一个总体比值。后一种操作会让干质量较大的样品贡献更多权重，回答的是整批干材料合计对应多少水。本章选择等权样品平均，是为了练习逐条记录计算后再分组汇总；更详细的权重问题将在第十二章讨论。把汇总的对象说清楚，可以防止一个熟悉的“平均”符号掩盖了实际比较单位。

这组教学记录的用途是演示结构与计算规则。图上两组结果不同，说明在这些给定输入下怎样得到不同汇总；如果要在真实研究中比较处理条件，还需要相应的实验设计、足够的独立样品和测量说明。数据结构应为这些信息保留位置，例如批次、时间和处理浓度。先让每个数有明确身份，再逐步增加所需字段，能够使后来的统计分析建立在可以追踪的实验对象上。

完整代码：从原始记录到可检查的结果

下面的脚本把六条构造记录直接写在开头，不需要联网获取数据。它先检查编号唯一性，建立按编号查找的字典，然后逐条计算吸液量，并分别保存原始记录和带结果的记录。for record in records表示依次取出列表中的每条记录，缩进语句对当前记录执行；if根据条件选择处理分支。下一章会详细讲循环与函数，本章先把它们读作“对每条记录应用同一规则”，注意输入和结果怎样保持联系。

代码还展示了复制中的一个细节。alias = records让两个名字指向同一个列表，修改其中的字典会通过另一个名字看见；仅复制最外层列表，也仍可能让内部字典被共享。copy.deepcopy(records)则为本例建立独立的嵌套记录，修改副本不会改变原始值。完整脚本用一次明确改动检验这种差别，随后确认原始A01干质量仍为1.20 g。理解名字、容器与内部对象的关系，可以避免在“试着修改一下”时无意改变正在分析的数据。

本例计算结果时使用record.copy()复制一条字典，再增加uptake_g_per_g字段。由于这些原始字段只包含字符串、数字和None，浅复制足以让新增字段与原字典分开。若字段里还嵌着可修改的列表，例如一个样品的全部时间序列，就需要重新考虑共享关系。这不是要求每次都做最深的复制，而是要求清楚哪一层对象会被改动，哪些对象应继续作为共同的原始记录。
